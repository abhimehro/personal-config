## 2024-05-24 - Pre-compile token regexes efficiently
**Learning:** When searching strings against a large dictionary of tokens using regex, looping over many individually compiled regex patterns in `search()` operations is highly inefficient. Sorting the dictionary keys by length (longest first) and compiling them into a single regular expression with `({'|'.join(...)})` alongside non-overlapping string boundary matchers enables the regex engine to do a single efficient O(N) scan using `finditer()`, speeding up processing by >70% while maintaining correct greedy matching. Also, to prevent duplicate penalties from `finditer` matching multiple occurrences of the same bad marker, always track matches in a `set()`.
**Action:** Always prefer a single compiled alternation regex over looping through a dictionary of individual patterns. Sort tokens by length descending for greedy matching if prefixes overlap. Track results using a set if matches should be unique per string.
