# MCP Server Secrets Management

This document explains how to manage API keys and secrets for MCP (Model
Context Protocol) servers securely.

> **SECURITY:** Committed files must never contain live API keys. Use either
> 1Password CLI refs (`op://…`) in MCP templates, or unmistakably fake
> placeholders (`REPLACE_WITH_…`) in `.env.example`-style files.

## Overview

The canonical MCP server list lives in
[`mcp-configs/mcp-servers.template.json`](../mcp-configs/mcp-servers.template.json).
It holds **only** `op://` refs. Runtime configs with live keys are generated by
`scripts/generate-mcp-configs.sh` and live **outside** the repo (or are
gitignored). See [`mcp-configs/README.md`](../mcp-configs/README.md).

## Preferred pattern: 1Password CLI refs

Committed templates use 1Password CLI injection paths — these are **not** live
credentials; they resolve only when `op inject` / `op run` runs locally:

```json
{
  "mcpServers": {
    "Brave Search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "op://Personal/BRAVE_API_KEY/credential"
      }
    }
  }
}
```

Windsurf / Windsurf Next templates under `.codeium/*/mcp_config.json.template`
follow the same rule: committed = `op://` only; live resolved configs are
gitignored.

## Local secrets (generated / hand-edited — never commit)

Primary generated locations (examples):

| Client   | Path                                              |
| -------- | ------------------------------------------------- |
| Cursor   | `~/.cursor/mcp.json`                              |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` (gitignored)|
| Shared   | `~/.config/mcp-servers/mcp-config.json` (optional)|

Regenerate with:

```bash
./scripts/generate-mcp-configs.sh
```

### Example of a *local* filled config (do not commit)

When documenting a filled local file, mark values so they cannot be mistaken for
real credentials:

```json
{
  "mcpServers": {
    "Brave Search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "REPLACE_WITH_YOUR_BRAVE_API_KEY"
      }
    },
    "Exa": {
      "command": "npx",
      "args": ["exa-mcp-server"],
      "env": {
        "EXA_API_KEY": "$EXA_API_KEY"
      }
    }
  }
}
```

## Environment variables alternative

Copy `.env.example` → `.env` (never commit `.env`) and replace every
`REPLACE_WITH_*` marker:

```bash
cp .env.example .env
# Edit .env — replace REPLACE_WITH_* values with real keys from 1Password
```

Then reference env vars in a local MCP config:

```json
"env": {
  "BRAVE_API_KEY": "$BRAVE_API_KEY",
  "EXA_API_KEY": "$EXA_API_KEY"
}
```

## Placeholder convention (repo-wide)

| Pattern                         | Where used                         | Meaning                                      |
| ------------------------------- | ---------------------------------- | -------------------------------------------- |
| `op://Personal/<ITEM>/credential` | MCP `*.template` / `*.template.json` | 1Password ref — safe to commit             |
| `REPLACE_WITH_YOUR_<NAME>`      | `.env.example`, docs examples      | Human must replace; never a real secret      |
| Live key material               | Generated / `~/.config/…` only     | **Never** commit                             |

Do **not** use ambiguous phrases like `your_actual_…_here` in committed docs.

## Symlink strategy for multiple workplaces

### Option 1: Symlink the entire config

```bash
# In each workplace's .cursor directory
ln -s ~/.config/mcp-servers/mcp-config.json .cursor/mcp.json
```

### Option 2: Prefer the generator

Prefer `./scripts/generate-mcp-configs.sh` over hand-copying so every client
stays aligned with the canonical template.

## Security best practices

- Never commit API keys to version control
- Prefer `op://` in templates; resolve with `op inject` at generate time
- Use different keys for development vs production if applicable
- Rotate keys regularly through the respective service dashboards
- Audit access regularly to ensure no keys are exposed
- Keep placeholders unmistakably fake (`REPLACE_WITH_*`) so scanners and humans
  do not confuse them with live credentials

## Troubleshooting

### MCP Server Not Starting

- Check that API keys are correctly set (or `op://` refs resolve)
- Verify the JSON syntax is valid
- Ensure the generated config path for your client exists and is readable

### Keys Not Working

- Verify the key hasn't expired
- Check if the key has the required permissions
- Ensure you're not hitting rate limits
- Confirm `op signin` / unlock before regenerating

### Workplace-Specific Issues

- Each workplace may have its own MCP config
- Check which config file is being loaded
- Regenerate with `./scripts/generate-mcp-configs.sh` for consistency
